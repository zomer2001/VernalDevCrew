## 本轮发现并修复

### 模型输出规则与平台校验不一致

模型返回问题编号 `Q1`、`Q2`，平台要求 `Q-01`、`Q-02`。原实现仅在应用内部校验编号，导出的 JSON Schema 没有对应约束，导致原生校验节点先通过，平台取回结果后才拒收。

现在将编号正则和非空问题约束直接写入字段定义，生成的 JSON Schema 和平台校验使用同一份约定。需求评估提示也明确编号格式。Python 和 Node 两种原生校验器均会在工作流内拒绝错误格式，使既有返工步骤能及时反馈给模型。

对未通过应用格式校验的结果，页面改为简洁说明，完整错误仍写入执行日志，原始结果继续保留。没有放宽编号规则，也没有修改本次真实产物以伪装验收成功。

### 验收回调地址仍指向默认端口

真实原生工单中的上下文回调地址使用了 8787，而验收网页服务运行在 8790。本次本机 Runner 通过共享文件路径读取上下文，因此这项问题没有阻止模型运行，但远端执行机缺少该路径时会访问错误端口。

验收脚本现在让回调地址默认跟随实际监听端口。显式设置的 `VERNAL_PUBLIC_URL` 仍优先保留，便于远端执行机使用可访问的服务地址。
