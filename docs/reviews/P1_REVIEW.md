## 2. Spec Kit 用在哪里，怎么使用

1. 在架构协作页启用功能规格流程，选择标准或轻量预设。已有结构化 PRD 的项目需要显式迁移，原文件保留。存在未结束任务、无法结构化的历史需求或路径冲突时会拒绝自动迁移。
2. 先建立项目宪章。它同时进入已有 LoopForge 项目规则和每个工作包的输入上下文。
3. 为每个功能建立独立编号，填写目标和资料，执行整理功能规格。后续修改继续围绕同一功能修订，不建立第二份权威 PRD。
4. 执行澄清需求边界和质量检查。负责人回答关键问题后，在原有流程门禁中批准当前 SRS。规格或宪章改变后需重新审查。
5. 执行制定技术方案和拆解实施任务。任务草案保留可阅读条目，同时携带可验证元数据。
6. 执行一致性检查，再预览可执行工作包。发现严重问题、漏掉 P0 需求、循环依赖或越权路径时不能发布。
7. 发布后进入现有工作台。继续使用原计划批准、启动、验证和人工审查入口。重复发布相同指纹不会生成重复任务。
8. 在功能规格面板查看步骤交接，在任务抽屉的验证页查看开发和审查交接。验证文字必须明确区分已执行检查和未执行检查。

外部直接修改规格文件不会自动变成批准来源。可使用备份并恢复文件副本恢复当前修订，外部内容先备份到项目状态目录；需要采纳外部内容时，在恢复后通过编辑器保存为新修订。

## 3. 自审发现与修复

1. 修复规格标题正则误吞正文的问题，拒绝重复章节、未识别需求和错误的验收条目格式。
2. 防止旧 PRD、圆桌综合输出、计划 API 和 SRS 编辑器重新成为第二来源。历史 PRD 迁移保留需求、错误约定、验收红线及原始说明。
3. 澄清问题不能通过手动改正文消除。新关键问题使已有批准失效，默认值改选不会在正文保留互相冲突的同一问题答案。
4. 已发布任务不能被普通排期接口改写。没有冻结工作包的任务不能在启用项目中执行，临时契约补丁和旧转向入口也不能绕过编译器派发。
5. 运行期间拒绝替换规格来源。规划生成期间来源发生变化时，结果拒收并保留失败记录；异常和取消也会结束运行记录。
6. 加入契约指纹、资产锁和任务字段复核，阻止过期或被改写的工作包继续执行。发布时重新计算预览指纹，避免用户确认旧预览。
7. 编码任务只有开发和审查两个节点的交接便签均有效时才通过交接检查。模拟缺少审查便签的场景会明确失败。
8. 修复新面板切换项目时的过期响应问题。所有正文和问题文本转义输出，编辑保存带当前修订号。
9. 保留旧规划校验脚本的缺文件错误提示，避免破坏既有调用和测试。
10. 启用规格流程时，在现有项目模板中补齐需求审批门禁，防止默认轻量模板隐藏必须完成的 SRS 审批入口；其余阶段设置保留。

## 5. P1 的适用范围

本批可用于单个功能、单个里程碑、写入范围清楚的增量任务。一个工作包可以合并多个实施步骤，也可以发布多个互不重叠的工作包。

编译阶段检查验证命令是否为空、能否分词和解析；不执行验证命令，也不把命令存在当作测试通过。资产锚点当前覆盖 Spec Kit 与中文预设，完整 Skill、SOP、决策版本和最终发布证据清单仍需后续批次补齐。

完整资源锁、跨工作包重叠写入调度、运行中变更传播、受影响任务选择性重编译和旧结果隔离，仍属于 P3。当前采用明确阻断：来源改变后旧工作包不可继续执行；已有任务不能原地替换；契约基线改变也会要求重新评审后续实施。已结束里程碑不能接收新工作包。

本批没有改造全部需求入口、自动任务分类或默认入口路由，这些属于 P2；没有完成富文本规范文档和统一原生抽屉，这些属于后续页面批次。现有轻量面板用于先验证来源、审批、编译和执行的连通性。

数据库事务不能和普通文件写入组成一个原子事务。异常中断留下文件漂移时，后续校验会阻断执行；恢复入口用于保留外部内容后修复副本。首次发布如果在写文件后异常中断，需先备份并移开尚未纳管的文件，再重新保存。

## 6. 负责人验收步骤

在本检出目录运行：

```bash
bash scripts/start_p1_review.sh
```

打开 <http://127.0.0.1:8789/#/collaboration>。原 P0 页面继续使用 8788。

启动脚本只准备独立样例工作区，已有测试修改会保留。样例包含宪章、保存回答的规格和一个关键澄清问题。脚本不会调用模型、自动批准门禁或启动编码。

建议依次检查：

1. 打开功能规格面板，确认能看到 `001-save` 和数据保留时长的问题。
2. 未回答时尝试批准 SRS，确认不能通过；回答后检查新增修订和只读 SRS，再批准。
3. 修改规格并保存，确认旧批准失效；对同一修订重复或过期保存应有冲突提示。
4. 选择实际可用的执行池，确认 Runner 在线、凭据有效、所用角色配置明确模型，再运行技术方案、任务和一致性检查。
5. 预览并发布工作包，确认现有工作台出现任务，第二次发布不重复；批准计划后再启动真实执行。
6. 查看开发和审查交接便签，复核真实测试与交付产物。

完成上述真实执行与页面验收后，再决定是否合并 P1，以及是否进入 P2。
