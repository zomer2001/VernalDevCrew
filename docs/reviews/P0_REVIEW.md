## 自审修正

1. 生成的规范文档原先没有进入既有 Git 归档流程，导致后续工作区检查认为存在未提交文件。现在只归档本次真正生成的文档，避免空列表意外扩大暂存范围。
2. 新门禁曾错误阻塞没有架构文档义务的旧轻量项目。现在按既有流程定义判断兼容边界；已经绑定文档的门禁仍严格校验。
3. 对外部直接新增详设成员、修改结构化详设但不改 Markdown 的情况补齐检查。新增、缺失或变更成员均不得沿用旧批准，其他里程碑不受影响。
4. 补齐并发编辑、双数据库连接发起审批、文件替换失败回滚、数据库重开与旧页错批的验证。
5. 独立启动暴露了包初始化顺序造成的循环导入，已修正并加入全新 Python 进程的导入回归测试。
6. 规范需求数组明确清空时，旧 Markdown 不得重新提供已删除需求，已增加回归测试。
7. 原追溯测试曾把完整快照标识填进补丁标识字段，已改为真实补丁产物，保留生产路径的显式错误行为。
8. 实际页面导出的追溯下载地址缺少项目标识，已登录用户会收到无权访问提示。现在 CSV 与 DOCX 均携带当前项目，复用文档面板时也更新链接；新增 Node 回归检查覆盖项目切换、编号编码和清空作用域。

原有测试中专门验证 CI 或候选审查的用例，显式关闭与用例无关的文档阶段。新版独立探针另外验证真实文档门禁，生产代码没有通过统一关闭门禁来获得通过结果。
