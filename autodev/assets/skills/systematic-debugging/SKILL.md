# Systematic Root-Cause Debugging

当测试失败、命令报错或任务被打回返工（Rework）时，严禁未经分析直接盲目修改多处代码：

1. **稳定复现与精确读栈**：
   - 完整阅读报错堆栈、退出码和失败断言行号，区分是「环境/路径导入问题」「契约字段不一致」还是「业务状态逻辑缺陷」。
2. **单点假设验证**：
   - 每次只针对一个明确假设定位问题源头（可编写最小复现命令核实输入输出），不要靠注释掉断言、放宽校验或吞掉异常（`except Exception: pass`）来掩盖 Bug。
3. **最小外科手术补丁与回归**：
   - 在允许修改路径白名单内实施最小修复，补充一条针对该缺陷的防回归用例，重跑全部验证命令确认旧功能零退化。
