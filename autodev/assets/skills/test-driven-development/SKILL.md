# Strict Test-Driven Development (TDD)

实现任何核心业务模块、引擎算法或后端接口时，遵循「先红后绿再整洁」纪律：

1. **契约先行，先写可失败的真实断言（Red）**：
   - 仔细对照上游冻结契约（如 `contracts/`）与任务验收标准，先编写覆盖正常主路径、边界值（空输入、极值、重复调用）及错误分支的自动化测试。
   - 严禁编写 `assert True`、只测 Mock 返回值不测真实逻辑的“假测试/空壳测试”。
2. **最小完备实现（Green）**：
   - 编写清晰、无冗余占位的生产代码使全部测试真实通过，不臆造需求之外的过度工程（YAGNI）。
3. **自净重构与全量门禁复核（Refactor）**：
   - 清理重复逻辑与未使用的导入，逐条运行任务卡片中的所有「必跑验证命令」，确认退出码全部为 `0` 后再打包提交。
