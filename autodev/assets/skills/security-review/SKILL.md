# Contract, Territory & Security Review Checklist

作为独立质量审查官（Reviewer），按以下四项硬指标逐一核验工作区代码与产物：

1. **验证命令真实复跑**：
   - 亲自执行需求列出的「必跑验证命令」，确认退出码为 `0`；打开测试文件抽查断言是否测试了真实行为而非空壳占位。
2. **目录领地与契约一致性**：
   - 核查所有新增/修改文件是否严格处于「允许修改路径白名单」内，未私自篡改冻结契约（`contracts/`）或其他研发组私有目录。
   - 检查导出的函数签名、数据结构字段名及类型是否与上游契约 100% 吻合。
3. **常见安全与健壮性底线**：
   - 排查硬编码密钥/Token、命令注入、路径穿越（`..`）、未转义的 `innerHTML` XSS 以及死循环阻塞风险。
4. **结构化审查结论**：
   - 在 `review-report.md` 首行明确写出 `# PASS` 或 `# REJECT`：通过时简述核验命令与结果；打回时用大白话逐条列出「问题文件 + 具体原因 + 明确修改要求」，切勿因纯代码风格偏好无故打回。
